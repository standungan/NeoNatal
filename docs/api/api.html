Neonatal Care API

HTTP reference for the FastAPI backend behind the NICU dashboard, the Flutter app and the incubator sensor rigs. Generated from the application's own OpenAPI schema, so it describes the code as it is deployed rather than as it is remembered.

Authorization: Bearer <jwt>

People. Issued by POST /api/v1/auth/login and carrying the role — admin, perawat or dokter — that every endpoint below is gated on.

X-Device-Key: <key>

Incubator hardware. Minted once per incubator and stored only as a SHA-256. It resolves device → incubator → the baby currently assigned, which is why a rig never names a patient.

GET/api/v1/incubators/{incubator_id}/streamany signed-in role

Live sensor readings for one incubator as Server-Sent Events.

Design notes

SSE rather than a WebSocket because telemetry is one-way: this rides the dashboard's existing cookie->Bearer proxy unchanged, reconnects natively in the browser, and needs no short-lived ticket for the client to authenticate.

On connect the ring buffer is replayed so a chart opened mid-stream is never blank, then new readings arrive as they are ingested. A comment line is sent every 15 s so idle proxies do not close the connection.

Telemetry (legacy)

Prototype-firmware ingest, identified by a payload label rather than a key. Answers 404 unless LEGACY_SENSOR_INGEST is enabled, because it authenticates nobody.

POST/api/sensorspublic

Ingest from prototype firmware that predates device keys.

Design notes

Nothing authenticates the caller here — anything able to reach this port can write vitals — so it answers 404 unless LEGACY_SENSOR_INGEST is enabled, which keeps it a lab-bench affordance rather than something that can quietly reach a real deployment.

The payload's `baby_id` is ignored; the baby is resolved from the active assignment exactly as on the authenticated path.
